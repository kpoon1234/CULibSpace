# Test Case Design — EPIC 7: Facility & Issue Management

การทดสอบแบบ **Black-box** อัตโนมัติด้วย Playwright ออกแบบจาก Acceptance Criteria (AC)
ใน Product Backlog ไม่ใช่จากโค้ด ผลที่คาดหวังจึงยึดตาม AC เป็นหลัก ถ้าระบบทำงานต่างจาก AC
ให้บันทึกเป็น defect หรือข้อสังเกต

## เทคนิคที่ใช้

| ย่อ | เทคนิค | ใช้กับ |
|---|---|---|
| EP | Equivalence Partitioning — แบ่งข้อมูลเป็นกลุ่มถูก/ผิด แล้วเลือกตัวแทนกลุ่มละ 1 ค่า | ฟอร์มแจ้งปัญหา, ตัวกรอง, ฟอร์มตารางเวลา |
| BVA | Boundary Value Analysis — ทดสอบค่าที่ขอบ (min−1, min, max, max+1) | ความยาวข้อความ, booking rules, วันที่/เวลา |
| ST | State Transition — ทดสอบการเปลี่ยนสถานะ | สถานะ issue |
| DT | Decision Table — ทดสอบผลจากเงื่อนไขหลายตัวรวมกัน | สถานะ + ปิดโต๊ะ, กฎข้ามช่อง |

## เงื่อนไขร่วม

- **Session:** ใช้ session จาก `auth.setup.ts` ได้แก่ **USER** (Alice) และ **ADMIN**
- **กติกา DB** (ดู `e2e/README.md`): สร้างข้อมูลเองโดยใส่ timestamp, คืนค่าที่เปลี่ยนการทำงานของแอปใน `afterEach` และไม่เช็กจำนวนแถวแบบตายตัว
- **รหัส test case:** `TC-<US>-<ลำดับ>` เช่น `TC-7.3-04`
- **ตอนรันจริง:** ให้เติมคอลัมน์ "ผลจริง" และ "ผ่าน/ไม่ผ่าน" ในรายงาน

**ขั้นตอนหลัก (USER):** หน้าแรก → ปุ่ม **Report Issue** → หน้า `/zones` → เลือกโต๊ะ →
**Report an issue with this table** → ฟอร์มแจ้งปัญหา (แสดงโต๊ะ, โซน, เวลา และช่องรายละเอียด)

|---|---|---|---|
| TC-7.1-01 | EP | เปิดฟังก์ชันแจ้งปัญหาจากหน้าแรก | ไปถึงฟอร์มแจ้งปัญหา และเห็นรหัสโต๊ะ, โซน และเวลาที่แจ้ง |
| TC-7.1-02 | EP (valid) | รายละเอียด `E2E <timestamp> outlet broken` | ข้อความ **Issue Report Successful** และ issue ใหม่นี้ไปโผล่ในหน้า admin |
| TC-7.1-03 | EP (invalid) | รายละเอียดว่าง | ส่งไม่ได้ และมีข้อความบอกว่าช่องไหนขาด |

| TC-7.1-05 | BVA | 4 ตัวอักษร (min−1) | ส่งไม่ได้ |
| TC-7.1-06 | BVA | 5 ตัวอักษร (min) | ส่งได้ |

> - US7-1 ระบุว่าแนบ **รูปภาพ** ได้ แต่ฟอร์มยังไม่มีช่องอัปโหลด ให้บันทึกว่ายังไม่ได้ทำ (ไม่อยู่ในขอบเขตของการทดสอบ)

| TC-7.2-08 | EP | ค้นหาด้วยเลขโต๊ะ | ทุกแถวที่เห็นเป็นโต๊ะนั้น |

## US7-3 อัปเดตสถานะ issue (ผู้รับผิดชอบ: คุณ)

**เงื่อนไขก่อนเริ่ม:** สร้าง issue ใหม่ทุกครั้งผ่าน USER ก่อน แล้วใช้ ADMIN ค้นหาด้วย `E2E <timestamp>`

**afterEach:** ตั้ง issue ที่สร้างให้เป็น **Completed** และไม่ปิดโต๊ะ เพื่อให้โต๊ะเปิดใช้ได้ตามเดิมแม้เทสต์จะ fail

**State Transition — สถานะ issue**

```
Pending ──► In Progress ──► Completed
   │                            │
   └────────► Completed ◄───────┘ (เปิดใหม่: Completed ──► Pending)
```

| ID | เทคนิค | กรณี / ข้อมูล | ผลที่คาดหวัง (ตาม AC) |
|---|---|---|---|
| TC-7.3-01 | ST | Pending → **In Progress** แล้ว Save | ข้อความ `Changes to issue #<id> were saved.` และ reload แล้วยังเป็น In Progress |
| TC-7.3-02 | ST | In Progress → **Completed** | บันทึกได้ และสถานะเป็น Completed |
| TC-7.3-03 | ST | Pending → **Completed** โดยตรง | บันทึกได้ |
| TC-7.3-04 | ST | Completed → **Pending** (เปิดใหม่) | บันทึกได้ และสถานะเป็น Pending |
| TC-7.3-05 | EP | เพิ่ม note `E2E note <timestamp>` แต่ไม่เปลี่ยนสถานะ | บันทึกได้ และ reload แล้วยังเห็น note |
| TC-7.3-06 | BVA | note ยาว 2000 ตัว (max) | บันทึกได้ |
| TC-7.3-07 | BVA | พยายามพิมพ์ note 2001 ตัว (max+1) | ช่องรับได้สูงสุด 2000 ตัว |
| TC-7.3-08 | EP | ไม่แก้อะไรเลย | ปุ่ม Save กดไม่ได้ หรือกดแล้วไม่เกิดการเปลี่ยนแปลง |

**Decision Table — สถานะ + "Close table during repair" → สถานะโต๊ะบนผัง (`/zones`)**

| ID | สถานะ | ติ๊กปิดโต๊ะ | ผลที่คาดหวัง |
|---|---|---|---|
| TC-7.3-09 | In Progress | ✔ | โต๊ะนั้นแสดงเป็น **Closed** และจองไม่ได้ (AC: "reflect facility availability changes") |
| TC-7.3-10 | In Progress | ✘ | โต๊ะไม่ถูกปิดเพราะ issue นี้ |
| TC-7.3-11 | Pending | (ไม่มีช่องให้ติ๊ก) | ตัวเลือกปิดโต๊ะไม่แสดง และโต๊ะไม่ถูกปิด |
| TC-7.3-12 | In Progress ✔ → **Completed** | ถูกล้างเอง | โต๊ะกลับมาใช้ได้ ไม่ใช่ Closed |

## US7-4 ตั้งค่าตารางเวลาและกฎการจอง

### ส่วน A: ตารางเวลาเปิด-ปิด (ผู้รับผิดชอบ: เพื่อน)

**เงื่อนไขก่อนเริ่ม:** ใช้ ADMIN ที่ `/admin/settings` ชื่อ schedule ใช้ `E2E <timestamp>` และวันที่ใช้ปี **2030** เท่านั้น ห้ามใช้วันนี้ เพราะถ้าปิดห้องสมุดวันนี้จะกระทบทั้งระบบ

**afterEach:** ลบ schedule ที่สร้างทุกตัว

| ID | เทคนิค | กรณี / ข้อมูล | ผลที่คาดหวัง (ตาม AC) |
|---|---|---|---|
| TC-7.4-01 | EP | เปิดหน้าตั้งค่า | เห็นเวลาเปิด-ปิดปกติ และตารางพิเศษ เช่นช่วงสอบหรือวันหยุด |
| TC-7.4-02 | EP (valid) | เพิ่ม Regular: Set hours 08:00–20:00, 2030-01-10 ถึง 2030-01-20 | ข้อความ `Added "<name>".` และเห็นในรายการ |
| TC-7.4-03 | EP (valid) | เพิ่ม exception แบบ **Open 24 hours** | บันทึกได้ และแสดง "Open 24 hours" |
| TC-7.4-04 | EP (valid) | เพิ่ม exception แบบ **Closed** (Holiday) | บันทึกได้ และแสดง "Closed" |
| TC-7.4-05 | EP (invalid) | ชื่อว่าง | `Enter a name.` |
| TC-7.4-06 | EP (invalid) | ไม่เลือกวันเริ่ม หรือไม่เลือกวันจบ | `Choose a start date.` หรือ `Choose an end date.` |
| TC-7.4-07 | BVA | วันจบ = วันเริ่ม | บันทึกได้ (ขอบที่ยังถูกต้อง) |
| TC-7.4-08 | BVA | วันจบ = วันเริ่ม − 1 วัน | `End date cannot be before the start date.` |
| TC-7.4-09 | BVA | เวลาปิด = เวลาเปิด | `Closing time must be after opening time.` |
| TC-7.4-10 | BVA | เวลาปิด = เวลาเปิด + 1 นาที | บันทึกได้ |
| TC-7.4-11 | EP | แก้ชื่อ schedule ที่สร้าง | ข้อความ `Saved changes to "<name>".` |
| TC-7.4-12 | EP | ลบ schedule ที่สร้าง (กด Delete แล้วยืนยัน) | ข้อความ `Deleted "<name>".` และหายจากรายการ |

### ส่วน B: กฎการจอง (ผู้รับผิดชอบ: คุณ)

**เงื่อนไขก่อนเริ่ม:** ใช้ ADMIN ที่ `/admin/settings` และจดค่าเดิมทั้ง 5 ช่องไว้ก่อน

**afterEach:** ใส่ค่าเดิมกลับแล้วกด Save

**BVA — ขอบของแต่ละช่อง** (เขียนเป็น data-driven test ได้ คือวนลูปจากตารางนี้)

| Book ahead up to (days) | 1 | 365 | 0, 1, 365, 366 |
| Minimum behaviour score (points) | 0 | 100 | −1, 0, 100, 101 |
| Early check-in (minutes) | 1 | 180 | 0, 1, 180, 181 |
| No-show after (minutes) | 1 | 180 | 0, 1, 180, 181 |

| ID | เทคนิค | กรณี / ข้อมูล | ผลที่คาดหวัง (ตาม AC: "validates numeric values") |
|---|---|---|---|
| TC-7.4-13 | BVA (valid) | ค่า **min** และ **max** ของทุกช่อง (10 กรณี) | ข้อความ `Booking policy saved.` และ reload แล้วยังเห็นค่าที่ใส่ |

| TC-7.4-20 | EP | แก้ค่าแล้วกดยกเลิกหรือรีเซ็ต | ค่ากลับเป็นค่าที่บันทึกไว้ และไม่มีการบันทึก |
